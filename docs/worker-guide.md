# Віртуальний працівник: анатомія, два шляхи, що здати (бонус +10)

**Віртуальний працівник** — агент, якому дали роботу так, як дають її людині: роль, інструменти, межі, тригер,
канал для результату, перевірку і людину, яка ухвалює незворотні рішення. Сам агент — це модель, що в циклі
викликає інструменти (модель → інструмент → результат → модель…). Працівником його робить усе інше.

Чим це відрізняється від AI-функції в продукті (основне завдання): функція — **один виклик** моделі на дію
користувача, з фіксованою схемою відповіді, всередині вашого застосунку на Vercel. Працівник — **цикл** з багатьма
кроками й інструментами, працює окремо від продукту (у вас на комп'ютері, за розкладом, у контейнері чи GitHub
Actions) і виконує рутину команди чи агенції.

Корисні посилання: [README, бонус](../README.md#бонус-10-віртуальний-працівник) ·
[промпти K10–K14](prompts.md#бонус-віртуальний-працівник) · [моделі](models.md) ·
шаблони [`worker-claude-code/`](../materials/worker-claude-code/README.md),
[`worker-agent-sdk/`](../materials/worker-agent-sdk/README.md),
приклад [`virtual-accountant/`](../materials/virtual-accountant/README.md).

## Анатомія: дев'ять складових

Кожна складова — це питання, на яке у вашому репо має бути відповідь **файлом**, а не обіцянкою.

| Складова | Питання | Шлях 1 (Claude Code) | Шлях 2 (Agent SDK) |
|---|---|---|---|
| **Роль** | Яку роботу і для кого? | `AGENTS.md`, `description` у `SKILL.md` — «оголошення про вакансію», за яким скіл вмикається | `SYSTEM_PROMPT` у `src/options.ts` |
| **Інструменти** | Чим працює? | скрипти в `scripts/`, Read/Grep/Glob, Edit лише в `out/` | `tools: ["Write"]` + власний MCP-інструмент (`createSdkMcpServer` + `tool()`) |
| **Межі** | Чого не можна? | `.claude/settings.json` (allow / deny) + `--permission-mode dontAsk` | `permissionMode: "dontAsk"` + `allowedTools`; хук `PreToolUse` |
| **Пам'ять** | Що пам'ятає між запусками? | файли, які читає людина: `references/`, датовані звіти в `out/` | нічого (свідомо); кожен звіт — новий файл |
| **Тригер** | Коли починає? | людина в чаті; `claude -p` за розкладом (`run.sh` / `run.ps1`, cron, Планувальник завдань, GitHub Actions) | `npm start` вручну, за розкладом, у GitHub Actions |
| **Канал** | Куди віддає результат? | звіт у `out/`, JSON запуску в `out/runs/` | звіт у `out/`, рядок у консолі, JSON запуску |
| **Людина в контурі** | Що лишається людині? | закрити період, виправити, заплатити, надіслати | відповісти клієнту, гроші, доступи (`needs_human: true`) |
| **Перевіряльник** | Хто перевіряє роботу? | субагент у чистому контексті, лише читання, не бачить цифр оркестратора | функція в коді (`verifyTriage`): схема, повнота, межі |
| **Бюджет** | Скільки може витратити? | `--max-turns`, ліміти вашої підписки | `maxTurns`, `maxBudgetUsd` (лише варіант A), ліміт ключа |

**Головний принцип: рахує й перевіряє код, модель керує процесом і пояснює.** Правило лише в промпті («ніколи не
став від'ємний залишок») — слабке. Правило в коді (скрипт з кодом виходу, схема, хук) — сильне.

## Два шляхи

| | Шлях 1 — Claude Code як рушій | Шлях 2 — Claude Agent SDK |
|---|---|---|
| Що це | звичайний Claude Code, налаштований файлами: скіл, субагент, дозволи; без людини — `claude -p` | ваша програма на Node, яка запускає той самий агентний цикл через `query({ prompt, options })` |
| Шаблон | [`materials/worker-claude-code/`](../materials/worker-claude-code/README.md) (звіряльник оплат) | [`materials/worker-agent-sdk/`](../materials/worker-agent-sdk/README.md) (диспетчер заявок) |
| Модель і оплата | ваша підписка Claude (Pro, Max, Ultra, Team, Enterprise) — **лише особисте використання** | **A:** ваш платний ключ Anthropic — підтримується. **B:** ваш безкоштовний ключ OpenRouter — **експеримент, офіційно не підтримується** |
| Коду | мінімум: markdown + скрипти | програма на TypeScript, 23 офлайн-тести в шаблоні |
| Перевірка без моделі | `node scripts/reconcile.mjs …` (коди 0 / 1 / 2) | `npm run check`, `npm test`, `npm run dry-run` |
| Коли брати | є підписка; хочеться результату за вечір | немає підписки, або потрібна програма-сервіс з межами в коді |

**Курс ключа не дає.** Шлях 1 — на вашій підписці, шлях 2A — на вашому платному ключі, шлях 2B — на вашому
безкоштовному ключі OpenRouter. Немає ні підписки, ні бажання платити — шлях 2B як експеримент, і зламаний запуск з
чесним описом теж зараховуємо.

### Шлях 1: Claude Code

Покроково — у README шаблону. Що варто знати заздалегідь:

- **Без `--bare`.** `--bare` пропускає CLAUDE.md, скіли, субагенти й хуки і не бере вхід підпискою — для такого
  працівника це означає «працівника немає».
- **`--permission-mode dontAsk`** — усе, що не дозволено явно, відхиляється: без людини нема кому натиснути «так».
  Дозволи — точні команди (`Bash(node scripts/reconcile.mjs *)`), а не `Bash(*)`.
- **Шляхи запису обмежує лише правило `Edit(...)`**, правила `Write(...)` не діють: `Edit(/out/**)` (провідний `/` —
  від теки проєкту).
- **`.claude/settings.json` діє лише з теки, де запущено Claude Code.** Запустили з кореня іншого репо — вузькі
  дозволи працівника не діють.
- **`-p` без `--bare` виконує хуки з `.claude/settings.json` і сервери з `.mcp.json` теки без діалогу довіри.**
  Запускайте лише в теці, вміст якої знаєте.
- **GitHub Actions:** `anthropics/claude-code-action@v1` з `claude_code_oauth_token` (його друкує `claude setup-token`)
  — запуски йдуть у ліміти вашої підписки; токен — лише в GitHub Secrets.

### Шлях 2: Claude Agent SDK

Покроково — у README шаблону (`@anthropic-ai/claude-agent-sdk` 0.3.318). Що варто знати заздалегідь:

- **`tools` — які вбудовані інструменти існують; `allowedTools` — які виконуються без питань.** `allowedTools` нічого
  не вимикає. Для закритого працівника — вузький `tools` + `permissionMode: "dontAsk"`.
- **`options.env` замінює середовище процесу повністю**, а не доповнює: `env: { ...process.env, … }`.
- **Межа запису — у хуку `PreToolUse`**, а не лише в промпті: `src/guard.ts` відхиляє запис поза `out/`.
- **Не у функції Vercel:** SDK запускає підпроцес Claude Code (~320–342 МБ на платформу), більший за ліміт пакета
  функції (250 МБ), а функція на Hobby живе до 300 с. Працівник живе окремо; веб-застосунок може поставити задачу в
  чергу.
- **Варіант B (OpenRouter):** `ANTHROPIC_BASE_URL=https://openrouter.ai/api`, `ANTHROPIC_AUTH_TOKEN=<ваш ключ>`,
  `ANTHROPIC_API_KEY=""` (саме порожній) і всі класи моделей — на `:free` ID; шаблон виставляє це сам
  (`src/config.ts`). `total_cost_usd` і `maxBudgetUsd` рахуються за цінами Claude, тож для OpenRouter це не стеля
  витрат. Ліміт — ті самі 50 запитів на добу, а кожен крок циклу — запит. Моделі — у [models.md](models.md#робота-b--агентний-цикл-з-інструментами-бонус-шлях-2-варіант-b).

## Політика: чия підписка і для кого

- **Підписка Claude = особисте використання.** Ваш працівник на вашій підписці для вашої власної роботи — саме такий
  випадок.
- **Продукт для інших людей — лише з автентифікацією API-ключем.** Документація Agent SDK: «Unless previously
  approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their
  products, including agents built on the Claude Agent SDK». «Звіряльник для всієї агенції, де кожен натискає кнопку»
  — це вже продукт.
- Назвати продукт «Claude Code» не можна; «<ВашАгент> Powered by Claude» — можна (та сама сторінка документації).

## Два працівники автора: патерни

Обидва — справжні помічники автора курсу. Тут лише патерни: даних, назв і коду з них немає. Бухгалтер показаний
наживо на **вигаданій** копії (`materials/virtual-accountant/`), кладівник — лише на слайдах.

### Бухгалтер: Claude Code як рушій

Роль: перевірити чернетки податкової декларації ФОП, звірити дохід з банківськими виписками й актами, сказати, чи
можна подавати й платити. **Подає й платить людина.**

- **Рахують скрипти, а не модель.** Кожен скрипт друкує таблицю, потім `###JSON###`, і повертає ненульовий код
  виходу, якщо знайшов розбіжність. Модель викликає скрипт і пояснює результат.
- **Перевіряльник у чистому контексті, без підказок.** Окремий субагент з Read/Grep/Glob/Bash (без запису)
  отримує лише шляхи до першоджерел і перелік перевірок — не цифри оркестратора — і повертає вердикт у фіксованому
  форматі: `OK / ПРОБЛЕМИ`, що перевірено, власні ключові цифри, що не вдалося перевірити.
- **Ієрархія доказів.** Подана декларація > виписка й акт банку > експорт облікового сервісу > нотатки. Рядок
  «самоперевірка ✓» у згенерованому документі — твердження, а не доказ.
- **Три стани результату:** `OK / НЕ ПЛАТИТИ / НЕ ПЕРЕВІРЕНО`. «Внутрішньо узгоджено» і «перевірено за першоджерелами»
  — різні речі.
- **Урок, через який з'явилися правила:** два облікові сервіси дали однакові чернетки — і обидва помилялися (взяли
  дохід «нетто» замість «брутто»). **Збіг двох систем ≠ правильність.** Демо на вигаданому ФОП відтворює саме це:
  чернетки збігаються до копійки, арифметика сходиться, а база — ні; звірка за операціями показує, які операції й за
  яким правилом.
- **Одне джерело інструкцій:** `CLAUDE.md` — один рядок `@AGENTS.md`; уроки дописуються в скіл того ж дня.

### Кладівник: Agent SDK у контейнері

Роль: вести домашній каталог речей (кімнати → полиці → коробки → речі) як теку Markdown-файлів, з Telegram — текстом
і фото. Побудований на форку NanoClaw (MIT, © 2026 Gavriel, <https://github.com/nanocoai/nanoclaw>).

- **Рушій:** Node-процес на хості отримує повідомлення з Telegram і за розкладом (cron / інтервал / один раз)
  запускає `query()` Agent SDK у Docker-контейнері.
- **Плагін — лише скіл.** Нових інструментів не писали: `SKILL.md` вчить домовленостей каталогу, а вбудованих
  Read/Write/Edit/Glob/Grep досить. Працівник = інструкції + дані + наявні інструменти.
- **Межа доступу = змонтовані теки.** Агент працює з `bypassPermissions`, і це безпечно рівно настільки, наскільки
  вузькі монтування: контейнер бачить лише те, що в нього змонтовано; іншим групам — лише читання.
- **Урок:** головна група монтує **увесь корінь проєкту** з правом запису — а там лежить `.env`. Хук, що прибирає
  змінні з ключами з команд Bash, не допомагає, якщо агент може просто прочитати файл; а писати в корінь означає й
  змінити власні межі. **Межа діє лише тоді, коли агент не може її прочитати чи переписати.**
- **Правило лише в промпті** («ніколи не став від'ємний залишок») — слабке місце; правило розкладу (`schedule_task`)
  перевіряється в коді до запису — сильне.

### Що з цього взяти собі

1. Спершу «оголошення про вакансію»: роль, обсяг, тригер, список «ніколи».
2. Рахує й перевіряє код; модель оркеструє й пояснює.
3. Перевіряльник — у чистому контексті, з першоджерелами, без ваших висновків.
4. Мінімальні права: вузькі інструменти, точні команди, лише читання для всього, що не треба змінювати.
5. Секрети — за назвою й вузьким каналом, ніколи в промпті й у змонтованих теках; виходьте з того, що агент знайде
   все, що бачить.
6. Незворотний крок (надіслати, оплатити, опублікувати, змінити дані клієнта) — за людиною.
7. Пам'ять — звичайні файли, які людина може відкрити.
8. Golden cases для працівника: кілька наборів даних з відомим вердиктом, щоб перевіряти його після кожної зміни.

## Golden data для працівника

Те саме визначення eval, що й для AI-функції: прогін на задачах із відомими відповідями → бал. Для працівника задача —
**набір даних з відомим вердиктом**:

- **2–3 синтетичні набори**: один «чистий» (очікуване: OK) і один-два із закладеними помилками (очікуване: які саме
  проблеми). Як `data/2026-10` у `worker-claude-code` (дві навмисні помилки) чи `REQ-05` з ін'єкцією в
  `worker-agent-sdk/data/inbox.csv`.
- **Відповідь — поза текою працівника.** Якщо очікуване лежить там, де агент чи перевіряльник можуть його прочитати,
  перевірка перестає бути незалежною. У репо тримайте відповідь у тестах чи окремому файлі, який працівник не читає
  (його дозволи не дають доступу).
- Результат працівника на кожному наборі — у звіті: збіглося чи ні, і чому.

## Що здати (шаблон `docs/worker/README.md`)

Працівник — в **окремому публічному репо** (перевірка статична, за SHA; дані синтетичні). Шаблони наборів кладуть
звіти й журнали в `out/`, а `out/` — у `.gitignore`. Тому для здачі **скопіюйте** JSON одного запуску без людини і
його звіт у `docs/worker/runs/` і закомітьте. Перевірте, що в них немає ключів і справжніх даних.

Скопіюйте блок нижче в `docs/worker/README.md` свого репо працівника й заповніть:

```markdown
# <Назва працівника>

## Картка ролі
- Роль: <що робить, одним реченням>
- Для кого: <роль у команді чи агенції>
- Тригер: <чат / розклад (який) / подія>
- Канал результату: <файл у out/, повідомлення, JSON>
- Ніколи не робить: <3–5 пунктів: надсилати клієнтам, платити, змінювати першоджерела, ходити в мережу…>
- Шлях: <1 — Claude Code на власній підписці | 2A — Agent SDK, платний ключ | 2B — Agent SDK, OpenRouter, експеримент>

## Межі
- Де записано: <.claude/settings.json + --permission-mode dontAsk | tools + permissionMode + хук src/guard.ts>
- Дозволено: <точні команди й шляхи>
- Заборонено: <мережа, .env*, зміна власних інструкцій і даних…>

## Перевіряльник і людина в контурі
- Хто перевіряє: <субагент … / функція в коді …> і що саме
- Що лишається людині: <незворотний крок>

## Golden data
| Набір | Що закладено | Очікуваний вердикт | Результат працівника |
|---|---|---|---|

## Запуск без людини
- Команда: <…>
- Журнал: docs/worker/runs/<дата>.json, звіт: docs/worker/runs/<дата>-report.md

## Вартість і ліміти
- Кроків (num_turns): <…>; оцінка total_cost_usd: <…> (оцінка, не рахунок)
- Ліміти: <підписка / ключ Anthropic / OpenRouter 50 на добу> і чи вистачило
- Що зламалось і що варто змінити: <…>
```

Ключ, токен і `.env` у репо не потрапляють; журнал запуску — без значень змінних середовища.

## Безпека

- **Лише синтетичні дані.** Справжні фінанси, листи клієнтів, персональні дані — ні в репо, ні в запусках.
- **Жодних прод-доступів:** ключі Supabase, токени Vercel чи GitHub з правом запису у ваш продукт працівнику не
  потрібні.
- **Секрети** — у `.env` (у `.gitignore`) чи GitHub Secrets. Агент не читає `.env*`: заборону пишіть у дозволах
  (`deny`), а не лише в промпті.
- **Вміст вхідних даних — дані, а не інструкції.** Перевірте працівника на ін'єкції: заявка, лист чи рядок CSV з
  «ігноруй попередні інструкції» не має змінити його поведінку (промпт [K13](prompts.md#k13)).
