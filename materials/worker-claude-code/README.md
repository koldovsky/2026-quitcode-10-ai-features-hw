# Віртуальний працівник на Claude Code (бонус, шлях 1)

Шаблон віртуального працівника, у якого «рушій» (harness) — звичайний Claude Code на **вашій власній підписці**:
скіл-оркестратор, субагент-перевіряльник, детермінований скрипт і запуск без людини (`claude -p`) за розкладом.
Це узагальнений патерн «віртуального бухгалтера» автора курсу. Приклад ролі — **звіряльник оплат** на
синтетичних даних (`ТОВ «Приклад»`, клієнти А–Г): перед закриттям місяця звірити чернетку звіту з рахунками й
банківською випискою.

Шлях 2 (власна програма на Claude Agent SDK) — `materials/worker-agent-sdk/`.

## Що робить агента «віртуальним працівником»

Агент — це модель, що в циклі викликає інструменти. Працівником його роблять дев'ять речей, і кожна має місце
у файлах:

| Складова | Питання | Де в цьому шаблоні |
|---|---|---|
| **Роль** | Яку роботу виконує і для кого? | `AGENTS.md` («Роль»), `description` у `SKILL.md` — «оголошення про вакансію», за яким скіл вмикається |
| **Інструменти** | Чим працює? | `scripts/reconcile.mjs` (рахує), Read/Grep/Glob (читає), Edit лише в `out/` |
| **Межі** | Чого не можна? | `.claude/settings.json` (allow/deny), розділ «Межі» в `AGENTS.md`, `--permission-mode dontAsk` |
| **Пам'ять** | Що пам'ятає між запусками? | файли, які читає людина: `references/` (правила, профіль), `out/` (датовані звіти) |
| **Тригер** | Коли починає? | людина в чаті (`/reconciler data/2026-10`) або розклад (`run.sh` / `run.ps1` / GitHub Actions) |
| **Канал** | Куди віддає результат? | файл `out/YYYY-MM-DD Звірка <період>.md` + коротка відповідь у чаті / JSON запуску |
| **Людина в контурі** | Що лишається людині? | закриття періоду, виправлення чернетки, будь-яка оплата чи лист; агент лише показує, що виправити |
| **Перевіряльник** | Хто перевіряє роботу? | субагент `reconciler-verifier`: чистий контекст, лише читання, не бачить цифр оркестратора |
| **Бюджет** | Скільки може витратити? | `--max-turns 30`, `maxTurns: 15` у перевіряльника, ліміти вашої підписки |

Головний принцип: **рахують скрипти, перевіряє незалежний перевіряльник, агент керує процесом і пояснює.**

## Файли

```
AGENTS.md                         роль, ієрархія доказів, стани OK / ПРОБЛЕМИ / НЕ ПЕРЕВІРЕНО, межі
CLAUDE.md                         один рядок @AGENTS.md — одні інструкції для Claude Code та інших агентів
.claude/skills/reconciler/SKILL.md  оркестратор: процедури A (арифметика), B (звірка), D (перевіряльник), звіт
.claude/agents/reconciler-verifier.md  перевіряльник: tools Read, Grep, Glob, Bash; формат вердикту
.claude/settings.json             вузький allow / deny
scripts/reconcile.mjs             перевірка без залежностей: таблиця + ###JSON###, код виходу 0 / 1 / 2
references/rules.md, profile.json правила ролі й «відомі граблі»; власні назви компанії
data/2026-10/                     синтетичні рахунки, виписка і чернетка звіту з двома навмисними помилками
out/                              сюди працівник пише звіти; out/runs/ — JSON кожного запуску без людини
run.sh, run.ps1                   запуск без людини (cron / Планувальник завдань Windows)
.github/workflows/reconciler.yml  запуск за розкладом у GitHub Actions
```

## Як спробувати (10 хвилин)

Потрібні: Node 24 і Claude Code з входом у вашу підписку (`claude`, потім `/login`).

1. Скопіюйте теку `worker-claude-code` окремо (або зробіть з неї окреме приватне репо) і відкрийте термінал у ній.
2. Перевірка без моделі — скрипт сам по собі:

   ```bash
   node scripts/reconcile.mjs check-draft data/2026-10   # АРИФМЕТИКА: OK, код 0
   node scripts/reconcile.mjs reconcile data/2026-10     # ЗВІРКА: РОЗБІЖНОСТІ (5), код 1
   ```

   Чернетка узгоджена сама з собою, а наївна сума всіх надходжень (35 700,00) **точно збігається** з «оплачено» в
   чернетці — і обидві неправильні. За правилами: оплачено 29 500,00, борг 4 200,00 (рахунок INV-2026-104),
   переплати немає. Дві причини: рядок банку `B-0042` продубльовано в експорті (+2 000,00) і власний переказ
   4 200,00 зараховано як оплату INV-2026-104 через збіг суми.
3. Інтерактивно: запустіть `claude` у цій теці й напишіть «Звір оплати за жовтень 2026» або `/reconciler data/2026-10`.
   Очікуваний результат: стан **ПРОБЛЕМИ**, дві причини вище, вердикт перевіряльника, новий звіт у `out/`.
4. Без людини:

   ```bash
   ./run.sh 2026-10                                                           # bash, Git Bash, macOS, Linux
   powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 -Period 2026-10   # Windows
   ```

   Результат запуску (текст відповіді, кількість кроків, `total_cost_usd`) — у `out/runs/<час>.json`, звіт — у `out/`.

## Запуск без людини: що означають прапорці

Прапорці перевірено за довідкою CLI (`claude --help`, версія 2.1.318) і сторінкою
https://code.claude.com/docs/en/cli-reference.

| Прапорець | Навіщо |
|---|---|
| `-p "/reconciler data/2026-10"` | один запуск без інтерактиву; `/назва-скіла` у промпті Claude Code розгортає в скіл |
| `--permission-mode dontAsk` | усе, що не дозволено явно, — відмова: без людини нема кому натиснути «так» |
| `--allowedTools "…"` | що дозволено без питань — ті самі правила, що в `.claude/settings.json` |
| `--max-turns 30` | стеля кроків агента (у `--help` його немає, але він є в cli-reference; «лише в режимі print») |
| `--output-format json` | результат, кількість кроків і `total_cost_usd` (оцінка на боці клієнта, не рахунок) |

**Чому без `--bare`.** Документація радить `--bare` для скриптів, але він пропускає CLAUDE.md, скіли,
`.claude/agents` і хуки та **не читає** вхід підпискою чи `CLAUDE_CODE_OAUTH_TOKEN` (лише `ANTHROPIC_API_KEY`).
Для цього працівника це означає «працівника немає».

**Що `-p` завантажує без `--bare`:** хуки з `.claude/settings.json` і сервери з `.mcp.json` теки — без діалогу
довіри. Запускайте лише в теці, вміст якої ви знаєте.

**Git Bash на Windows** перетворює аргумент `/reconciler` на шлях Windows; `run.sh` вимикає це (`MSYS_NO_PATHCONV=1`).

## Розклад

**Windows — Планувальник завдань** (щомісяця 1-го о 09:00, від вашого користувача, коли ви в системі):

```powershell
schtasks /Create /TN "QuitCode reconciler" /SC MONTHLY /D 1 /ST 09:00 /TR "powershell -NoProfile -ExecutionPolicy Bypass -File \"D:\шлях\до\worker-claude-code\run.ps1\""
```

Без `-Period` обидва скрипти беруть демо-період `2026-10`. Для справжньої роботи змініть значення за
замовчуванням у `run.ps1` на `(Get-Date).AddMonths(-1).ToString('yyyy-MM')` (минулий місяць) або передавайте
`-Period` явно.

**Linux / macOS — cron** (`crontab -e`; у crontab знак `%` треба екранувати). Період — минулий місяць:

```cron
# Linux (GNU date)
0 9 1 * * cd /шлях/до/worker-claude-code && ./run.sh "$(date -d 'last month' +\%Y-\%m)" >> out/cron.log 2>&1
# macOS (BSD date)
0 9 1 * * cd /шлях/до/worker-claude-code && ./run.sh "$(date -v-1m +\%Y-\%m)" >> out/cron.log 2>&1
```

**GitHub Actions** — `.github/workflows/reconciler.yml` (працює, коли набір — корінь репо). Що каже документація
(https://code.claude.com/docs/en/github-actions, https://code.claude.com/docs/en/authentication):

- Дія `anthropics/claude-code-action@v1` приймає або `anthropic_api_key` (ключ з Claude Console), або
  `claude_code_oauth_token` — токен підписки Pro, Max, Ultra, Team чи Enterprise, який друкує `claude setup-token`.
  Токен діє рік, і запуски з ним ідуть у ліміти вашої підписки, а не в оплату API.
- Для секрету, спільного кільком репозиторіям, документація радить API-ключ: OAuth-токен прив'язаний до підписки
  людини, яка його створила.
- Розклад GitHub запускає лише з гілки за замовчуванням, а в публічних репо вимикає після 60 днів без активності.
- Щоб викликати скіл з репо, спершу `actions/checkout`, потім `/назва-скіла` як `prompt`.
- Токен і ключ — лише в GitHub Secrets, ніколи у файлах репо.

## Політика: чия підписка і для кого

- **Власна підписка = особисте використання.** Рекламовані ліміти Pro, Max і Ultra розраховані на звичайне
  індивідуальне використання Claude Code та Agent SDK (https://code.claude.com/docs/en/legal-and-compliance).
  Ваш працівник на вашій підписці для вашої власної роботи — це саме такий випадок.
- **Продукт для інших людей — лише з автентифікацією API-ключем** (Claude Console або хмарний провайдер).
  Anthropic не дозволяє стороннім розробникам вбудовувати вхід через claude.ai у свої застосунки чи пропускати
  запити своїх користувачів через підписку Free, Pro, Max чи Ultra (та сама сторінка; і
  https://code.claude.com/docs/en/agent-sdk/overview). Тобто «звіряльник для всієї агенції, де кожен натискає
  кнопку» — це вже продукт: API-ключ, а не ваш токен підписки.
- Дані: у цьому шаблоні — лише синтетичні. Справжні фінансові дані не кладіть у публічне репо й у звіти, які
  комусь показуєте.

## Як зробити свого працівника

1. **Роль.** Перепишіть «Роль» і «Межі» в `AGENTS.md` і `description` у `SKILL.md` під свою задачу в команді чи агенції
   (звіт за тиждень, розбір вхідних заявок, перевірка договору за чеклістом…).
2. **Скрипт.** Усе, що можна порахувати чи перевірити кодом, — у `scripts/`: таблиця, `###JSON###`, код виходу.
   Правило лише в промпті («ніколи не став від'ємний залишок») — слабке; правило в коді — сильне.
3. **Перевіряльник.** Залиште його лише з читанням і з забороною вірити цифрам у запиті. Опишіть формат вердикту.
4. **Межі.** Звузьте `allow` до точних команд; `deny` — на зміну власних інструкцій, даних і мережу.
5. **Golden cases для працівника.** Покладіть 2–3 набори синтетичних даних із відомою відповіддю (як `data/2026-10`
   з двома навмисними помилками) — це ваші golden cases: «вхід → очікуваний вердикт».
6. **Запуск без людини** — `run.sh` / `run.ps1` з вашим скілом; потім розклад.

## Як перевірити шаблон без моделі

```bash
node scripts/reconcile.mjs check-draft data/2026-10; echo $?   # 0
node scripts/reconcile.mjs reconcile data/2026-10; echo $?     # 1 (дві навмисні помилки)
node scripts/reconcile.mjs reconcile ../; echo $?              # 2 (тека поза data/ — відмова)
bash -n run.sh                                                 # синтаксис
node -e "JSON.parse(require('fs').readFileSync('.claude/settings.json','utf8'))"
```

## Бюджет і обмеження

- Перевіряльник приблизно подвоює витрату токенів фінальної перевірки — це ціна незалежності.
- `total_cost_usd` у JSON запуску — оцінка на боці клієнта, не рахунок; на підписці реальна межа — ліміти плану.
- Безкоштовні моделі OpenRouter у Claude Code офіційно не підтримуються (Anthropic не підтримує маршрутизацію
  Claude Code на не-Claude моделі через шлюзи; OpenRouter гарантує роботу лише з Anthropic). Якщо підписки немає —
  шлях 2 (`materials/worker-agent-sdk/`) з платним ключем або експериментом на безкоштовній моделі.
