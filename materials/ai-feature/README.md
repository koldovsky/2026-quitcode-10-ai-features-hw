# Набір «AI-функція» для зрізу 4

Готові файли для вашого репо розробника (зробленого з `2026-quitcode-06-project-template`): AI-функція, яка
перетворює вільний текст на **чернетку**, людина її перевіряє й лише тоді зберігає. Плюс перевірка якості на
10 golden cases від PM — офлайн у CI і живим прогоном за командою.

Приклад у наборі нейтральний: **розбір звернення клієнта в чернетку тікета** (категорія, пріоритет, дата,
короткий опис). Ваша функція — та, яку описує вимога PM вашого зрізу 4; приклад показує форму, а не домен.

## Навіщо це в роботі

AI-функція в продукті — це не «чат із моделлю», а звичайна функція з контрактом:

- **Схема відповіді.** Модель повертає JSON за схемою zod; усе, що не за схемою, — помилка, а не «майже чернетка».
- **Три стани.** `ok` — чернетку можна показати; `needs_info` — бракує даних (і що саме уточнити);
  `refused` — запит не про продукт або вхідний текст намагається керувати моделлю (prompt injection).
- **Людина в контурі.** Модель нічого не пише в базу. Пише ваш код — після того, як людина переглянула чернетку.
- **Ключ лише на сервері.** Ключ моделі ніколи не потрапляє в браузер, у git чи в чат.
- **Якість міряють, а не відчувають.** PM пише 10 golden cases («вхід → очікуване»), ви показуєте частку
  успіху (pass rate) — те саме визначення eval, що й у WS8: прогін на задачах із відомими відповідями → бал.

## Як підключити (крок за кроком)

Робіть це в гілці задачі (`task/<коротко>`), як будь-яку реалізацію: PR → CodeRabbit → злиття.

1. **Спершу специфікація.** AC зрізу 4 мають бути у вашій `openspec/specs/` (злитий PR «Специфікація»).
   Тест із AC ID, якого там ще немає, `npm run ac:coverage` позначає як ORPHAN, і job `conformance` червоний.
2. **ADR і залежності.** Нові залежності в шаблоні — «Спитай спершу» (AGENTS.md). Скопіюйте
   `docs/decisions/NNNN-ai-feature-openrouter.md` з наступним номером, перепишіть «Контекст» під свою функцію і
   поставте залежності з точними версіями:

   ```bash
   npm i --save-exact ai@7.0.162 @openrouter/ai-sdk-provider@3.1.0 zod@4.6.7 server-only@0.0.1
   ```

   Допишіть у `scripts` вашого `package.json` три рядки з `package.scripts-and-deps.json`:
   `eval`, `ai:models`, `ai:quota`.
3. **Файли.** Скопіюйте `src/`, `tests/`, `evals/`, `scripts/` і `vitest.eval.config.mts` з цього набору у
   відповідні місця репо. `src/app/ai-draft/actions.ts` перенесіть у теку сторінки вашого зрізу.
4. **Ключ.** Створіть **власний** безкоштовний ключ на https://openrouter.ai/settings/keys (платити нічого не треба).
   Допишіть вміст `env.example.add` у `.env.example`, а сам ключ — лише в `.env.local`:

   ```bash
   OPENROUTER_API_KEY=sk-or-...
   ```

   У Vercel: Project Settings → Environment Variables → `OPENROUTER_API_KEY` для Production і Preview.
   **Ніколи** з префіксом `NEXT_PUBLIC_`: такі змінні Next.js вбудовує в JavaScript для браузера.
5. **Ваш домен.** Змініть під вимогу PM:
   - `schema.ts` — поля чернетки (переліки замість вільних рядків там, де PM фіксує значення; «невідоме» = `null`);
   - `prompts/draft.ts` — інструкції й список полів; після кожної зміни збільшуйте `DRAFT_PROMPT_VERSION`;
   - `actions.ts` — запис у вашу таблицю в `confirmDraft` (під сесією користувача, RLS) і перевірку ролі, якщо
     функція лише для певної ролі.
6. **Golden cases PM.** Перенесіть кейси PM у `tests/fixtures/golden/cases.json`:
   `{ "id", "input", "expected": { поля, які PM фіксує точно }, "rubric": "що має / не має бути у вільному тексті" }`.
   Лише синтетичні дані: безкоштовні моделі можуть зберігати запити й навчатися на них.
7. **AC ID у тестах.** У `tests/golden.test.ts` замініть `AC-DRAFT-01` на ID критерію PM. Назва тесту — звичайний
   рядок, що **починається** з AC ID: `"AC-XXX-NN: golden $id"`. Шаблонний рядок `` `${id} …` `` і `.skip`/`.skipIf`
   `ac:coverage` не зараховує.
8. **Записи для реплею.** Заглушки в `recorded.json` замініть справжніми відповідями моделі (розділ
   «Перезапис записів» нижче), а потім додайте рядок AC у `docs/conformance.md` (`docs/conformance-rows.example.md`).

## Як перевірити

Офлайн, без ключа (так само це робить CI):

```bash
npm run typecheck     # next typegen + tsc
npm test              # golden cases (реплей) + збої + перевірка ключа
npm run lint          # 0 warnings
npm run ac:coverage   # рядок AC → код → тест
```

З мережею, без ключа: `npm run ai:models` — таблиця безкоштовних моделей сьогодні (SO — строга JSON-схема,
RF — JSON-режим, tools — інструменти) і чи всі моделі з `src/lib/ai/models.ts` ще існують. Код виходу 2 — якоїсь
моделі з ланцюжка вже немає.

З ключем у `.env.local`:

```bash
npm run ai:quota      # «використано X із 50, лишилось Y» за сьогодні (UTC)
npm run eval          # 10 кейсів наживо, по одному, з паузою 3 с; звіт → evals/reports/<дата>.md
```

`npm run eval` без ключа пропускає всі кейси — це не помилка. Перед прогоном він перевіряє, чи вистачить денного
ліміту, і зупиняється, якщо ні. Перший 429 посеред прогону теж зупиняє його: цей і решта кейсів — `NOT RUN` з
причиною в звіті, окремо від частки успіху; таймаут, помилка постачальника чи відповідь не за схемою — FAIL з причиною.

### Що саме перевіряє кожен рівень

| Рівень | Де | Що доводить | Чого НЕ доводить |
|---|---|---|---|
| Офлайн-реплей | `npm test`, CI | код навколо моделі: промпт із межею `<document>`, схема, стани, помилки, оцінювач | якість моделі |
| Перевірка ключа | `npm test`, CI | ключ лише в `openrouter.ts` із `server-only`, жодного `NEXT_PUBLIC_`, клієнтські файли його не імпортують | що ключа немає в історії git чи в логах |
| Живий прогін | `npm run eval`, вручну | частку успіху конкретних моделей на кейсах PM | що так буде завтра: безкоштовні моделі змінюються |

Звіт живого прогону показує, **яка модель** відповіла на кожен кейс: з ланцюжком fallback «9/10» — це, наприклад,
«7 на Gemma 31B + 2 на Super VL». Поля зі `expected` порівнюються точно; вільний текст (`summary`) — LLM-суддею
за `rubric`, лише в живому прогоні. Суддя — `nvidia/nemotron-3.5-super-vl:free`, інша родина, ніж основна Gemma;
якщо кейс віддала резервна Super VL, суддя тієї ж родини — це видно в колонці моделі.

## Перезапис записів (`RECORD=1`)

Після того як промпт стабільний, один живий прогін із записом:

```bash
RECORD=1 npm run eval                              # bash / Git Bash
$env:RECORD="1"; npm run eval; Remove-Item Env:RECORD   # PowerShell
```

У `recorded.json` потрапляють **лише успішні** відповіді (з `modelId`, датою й версією промпту), решта записів
лишається: прогін, обірваний лімітом, нічого не стирає. Тест «кожен golden case має запис, записаний поточною
версією промпту» падає, якщо `DRAFT_PROMPT_VERSION` змінено, а записи старі.

Кілька прогонів для частки успіху: `RUNS=2 npm run eval` (PowerShell: `$env:RUNS="2"`). Кожен прогін — до 20
запитів; без покупки кредитів на день їх 50, тож більше двох прогонів за день не вийде.

## Ліміти й дані — що треба знати

- **Ліміт — на акаунт:** 20 запитів/хв і 50/день (1000/день після одноразової покупки ≥ 10 кредитів).
  Додаткові ключі ліміту не збільшують. Ділять його всі, хто користується вашим застосунком: PM із golden cases,
  гості демо. Доба — UTC, у листопаді нова починається о 02:00 за Києвом.
- **Ланцюжок `models` не обходить цей ліміт:** він рятує від збою чи ліміту конкретного постачальника, а не від
  денного ліміту акаунта. Тому `maxRetries` — 0–1, а не типові 2.
- **Лише `:free` у ланцюжку:** платна модель у списку fallback оплачується за її ціною.
- **PDF:** без вказаного рушія OpenRouter бере **платний** `mistral-ocr`; у `models.ts` закріплено безкоштовний
  `cloudflare-ai`.
- **Gemma і JSON-схема:** у Gemma 4 немає `structured_outputs`, тож OpenRouter може проігнорувати схему. Тому поля
  повторено в промпті, а ворота — zod (`invalid_output`, якщо не за схемою).
- **Дані:** безкоштовні ендпоінти можуть зберігати запити й навчатися на них — лише синтетичні дані, жодних
  справжніх клієнтів, імен, паролів. Якщо OpenRouter відповідає помилкою на кшталт «no endpoints match your data
  policy», перевірте налаштування https://openrouter.ai/settings/privacy для безкоштовних моделей.
- **Список моделей змінюється:** перед роботою — `npm run ai:models`.

## Чого в наборі навмисно немає

- **Claude Agent SDK у функції Vercel.** SDK запускає підпроцес Claude Code (~320–342 МБ), а пакет функції
  Vercel Hobby — до 250 МБ і до 300 с роботи. Для функції в продукті достатньо одного виклику моделі; агент — це
  бонус «віртуальний працівник» (`materials/worker-*`).
- **Інструменти, які пишуть у базу від імені моделі.** Модель повертає чернетку, пише ваш код після людини.
- **Стрімінг.** Для форми з чернеткою він не потрібен.
