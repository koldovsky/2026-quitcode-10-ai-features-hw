# Віртуальний бухгалтер: демо на вигаданому ФОП

> **Усі дані вигадані.** ФОП «Тестенко Тест Тестович», РНОКПП `0000000000`, «Банк А», «Банк Б», контрагенти, суми, адреса й IBAN існують лише в цій теці. IBAN навмисно складено з нулів, тож він не проходить перевірку контрольної суми. Правила податкового обліку тут спрощено для навчання. Це **не податкова консультація**.

Це робоча копія патерну **«віртуальний працівник на Claude Code»**. Автор курсу користується таким помічником для власного обліку. Тут від справжнього лишився тільки патерн, усі дані замінено вигаданими:

- **роль і правила** в `AGENTS.md` (Claude Code читає їх через `CLAUDE.md` → `@AGENTS.md`);
- **скіл-оркестратор** `.claude/skills/accountant/SKILL.md` з процедурами А–Г;
- **рахують скрипти** `scripts/*.mjs`, а не модель. Це звичайний Node.js без залежностей: кожен скрипт друкує таблицю, потім `###JSON###`, і повертає ненульовий код виходу, якщо знайшов розбіжність;
- **незалежний перевіряльник** `.claude/agents/accountant-verifier.md` працює в чистому контексті. Він має лише Read/Grep/Glob/Bash і отримує тільки шляхи до першоджерел;
- **вузькі дозволи** в `.claude/settings.json`: автоматично дозволено лише три скрипти й читання, мережу заборонено, `data/`, `references/` і `scripts/` змінювати не можна;
- **людина в контурі**: помічник видає стан `OK / НЕ ПЛАТИТИ / НЕ ПЕРЕВІРЕНО`, а подає декларацію й платить людина.

## Що в теці

```
virtual-accountant/
├─ AGENTS.md, CLAUDE.md            роль, чотири залізні правила, як працювати
├─ .claude/
│  ├─ settings.json                дозволи: лише скрипти + читання; без мережі
│  ├─ skills/accountant/SKILL.md   оркестратор: процедури А–Г і формат результату
│  └─ agents/accountant-verifier.md  перевіряльник у чистому контексті
├─ references/
│  ├─ profile.md                   вигаданий профіль ФОП, власні рахунки
│  └─ rules.md                     демо-форма декларації, формули, правила, ієрархія доказів
├─ scripts/
│  ├─ check-declaration.mjs        арифметика чернеток (JSON або Markdown), порівняння, калькулятор
│  ├─ parse-statement.mjs          виписка CSV → операції з позначками
│  ├─ reconcile.mjs                дохід за операціями проти рядка 06 і книги доходів кожної чернетки
│  └─ lib.mjs                      спільний розбір CSV, дат, сум у копійках
├─ data/                           виписки двох банків, акти банків, подана декларація за I півріччя,
│                                  чернетки за III квартал від «Системи А» (JSON) і «Системи Б» (Markdown)
└─ out/                            сюди помічник пише датований звіт
```

## Як запустити в Claude Code

Знадобиться Claude Code на **власній підписці** (шлях 1 бонусу) і Node.js 18+. Ключ OpenRouter для цього демо не потрібен.

> **Живий прогін з моделлю ще не перевірено.** Перед заняттям вручну перевірено лише скрипти й дані (розділ «Без моделі» нижче). Опис поведінки в цьому розділі і в розділі «На що дивитися» — очікування, а не результат прогону. Невідомо, чи скіл підхопиться автоматично, чи субагент запуститься в режимі `-p` і як спрацюють правила дозволів `PowerShell(...)` на macOS чи Linux. Якщо щось не спрацює, запустіть офлайн-шлях.
>
> Перед кожним показом очистіть `out/*.md`. Звіт попереднього прогону містить готові цифри, і помічник чи перевіряльник можуть його прочитати.

1. Відкрийте термінал **у цій теці**. Claude Code бере `.claude/settings.json` лише з теки, де його запущено. Якщо запустити з кореня репозиторію, скіл може підхопитися, а вузькі дозволи цієї теки не діятимуть.

   ```bash
   cd materials/virtual-accountant
   claude
   ```

2. Введіть промпт:

   > Перевір чернетки декларації за III квартал 2026 і скажи, чи можна подавати й платити

3. Запис звіту в `out/` попросить дозволу: це навмисно, рішення лишається за людиною.

Головний крок без людини (той самий запуск з розкладу чи CI):

```bash
claude -p "Перевір чернетки декларації за III квартал 2026 і скажи, чи можна подавати й платити. Звіт запиши в out/." \
  --permission-mode dontAsk --allowedTools "Edit(./out/**)" --output-format json
```

`dontAsk` відхиляє все, що інакше попросило б дозволу. Працює лише дозволене в `settings.json` і в `--allowedTools`.

> **Спершу довіра до теки.** Дозволи з `.claude/settings.json` діють лише в теці, якій Claude Code довіряє. У свіжому клоні `claude -p` їх ігнорує (у stderr буде «Ignoring 7 permissions.allow entries … this workspace has not been trusted»), і в режимі `dontAsk` усі скрипти буде заблоковано. Тому спершу один раз запустіть `claude` інтерактивно в цій теці й підтвердіть довіру. Інший варіант — передати ті самі три скрипти явно: `--allowedTools "Read" "Glob" "Grep" "Bash(node scripts/parse-statement.mjs *)" "Bash(node scripts/check-declaration.mjs *)" "Bash(node scripts/reconcile.mjs *)" "Edit(./out/**)"`.

### Без моделі (офлайн)

Скрипти працюють і без Claude: так можна перевірити дані й побачити, що саме бачить помічник.

Команди нижче написано для bash (macOS, Linux, Git Bash на Windows). У PowerShell запишіть кожну команду в один рядок без `\`, а код виходу дивіться через `$LASTEXITCODE`.

```bash
node scripts/check-declaration.mjs data/draft-system-a-2026-Q3.json data/draft-system-b-2026-Q3.md \
  --prior data/declaration-2026-H1-submitted.json
node scripts/parse-statement.mjs data/bank-a-statement-2026-07-01--2026-10-05.csv --period 2026-Q3
node scripts/parse-statement.mjs data/bank-b-statement-2026-07-01--2026-10-05.csv --period 2026-Q3
node scripts/reconcile.mjs \
  --draft data/draft-system-a-2026-Q3.json --draft data/draft-system-b-2026-Q3.md \
  --statement data/bank-a-statement-2026-07-01--2026-10-05.csv data/bank-b-statement-2026-07-01--2026-10-05.csv \
  --act data/bank-a-acquiring-act-2026-Q3.csv data/bank-b-instalments-act-2026-Q3.csv \
  --prior data/declaration-2026-H1-submitted.json
echo "код виходу: $?"
```

## На що дивитися під час прогону

1. **Скрипти рахують.** У транскрипті видно виклики `node scripts/...`, а не суми, які модель склала «в голові». Код виходу — жорсткий сигнал: 0 чи 1.
2. **«Арифметика OK» — це ще не вердикт.** `check-declaration.mjs` перевіряє формули всередині чернетки. Чи правильна сама база (рядок 06), він не знає. Стежте, чи помічник на цьому зупиниться.
3. **«Дві системи зійшлися».** Чернетки з двох незалежних сервісів однакові до копійки, а в «Системі Б» ще й стоїть позначка «самоперевірка ✓». Чи вважає помічник це доказом? За правилами — ні: доказ дає лише звірка з виписками й актами.
4. **Звірка за операціями.** `reconcile.mjs` показує результат по кожній операції. Якщо є розбіжності, видно, які саме операції, на яку суму і за яким правилом. Подумайте, чому порівняння лише підсумків «на око» тут недостатнє.
5. **Перевіряльник у чистому контексті.** Відкрийте виклик субагента `accountant-verifier`. У промпті мають бути лише шляхи й перелік перевірок, без цифр оркестратора. Перевіряльник рахує самостійно і повертає `ВЕРДИКТ: OK | ПРОБЛЕМИ` у фіксованому форматі.
6. **Три стани й людина.** Фінальна відповідь містить стан кожної суми, обидва варіанти сум і найбезпечнішу наступну дію. Подати чи заплатити помічник не пропонує.

## Як перенести патерн на іншу роль

Візьміть ту саму анатомію і замініть зміст:

| Частина | У бухгалтера | Що написати для своєї ролі |
|---|---|---|
| Роль і межі | «готує й перевіряє, не подає й не платить» | що працівник робить, чого **ніколи** не робить, хто приймає рішення |
| Залізні правила | брутто; власні кошти ≠ дохід; експорт ≠ база; збіг систем ≠ правильність | 3–5 правил, які найчастіше порушують люди й сервіси у вашій ролі |
| Ієрархія доказів | подана декларація > виписка й акт > експорт сервісу > нотатки | які джерела у вас головні, а які лише «твердження» |
| Скрипти | арифметика, розбір виписок, звірка | усе, що можна порахувати чи перевірити детерміновано: суми, дати, схеми, дублікати, контрольні списки |
| Перевіряльник | перераховує з першоджерел, вердикт OK / ПРОБЛЕМИ | окремий субагент з вужчими інструментами і фіксованим форматом вердикту; не передавайте йому своїх висновків |
| Дозволи | лише свої скрипти, без мережі, першоджерела лише для читання | мінімум, без якого працівник не впорається |
| Людина в контурі | подає й платить людина | незворотний крок (надіслати, оплатити, опублікувати, змінити дані клієнта) лишається за людиною |
| Тригер | людина питає в чаті; `claude -p` за розкладом | чат, розклад, вебхук, нова заявка |
| Golden cases | контрольні квартали з відомим результатом, що зберігаються поза текою працівника | кілька прикладів з відомою відповіддю, щоб перевіряти працівника після кожної зміни |

Приклади ролей:
- PM, що перевіряє заявки на відповідність правилам;
- закупівельник, що звіряє рахунки з замовленнями;
- координатор розкладу, що шукає конфлікти;
- помічник з відпусток, що звіряє залишки днів із політикою.

## Інший шлях: Claude Agent SDK

Те саме можна зібрати на Agent SDK (шлях 2 бонусу) з платним ключем Anthropic API. Безкоштовна модель через **власний** ключ OpenRouter (`ANTHROPIC_BASE_URL=https://openrouter.ai/api`, `ANTHROPIC_AUTH_TOKEN=<ключ>`, `ANTHROPIC_API_KEY=""`) — це **експеримент, який не підтримується**. За документацією OpenRouter, ця схема гарантовано працює лише з моделями Anthropic, тож з іншими моделями виклики інструментів можуть ламатися. Безкоштовні ендпоінти можуть використовувати промпти для навчання, тому з ними — лише вигадані дані, як тут.

Підписку Claude можна використовувати лише для **власної** роботи. У продукт для інших людей вбудовуйте автентифікацію за API-ключем, а не вхід через claude.ai.
